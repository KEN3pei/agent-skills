# my-tasks

自分担当の GitHub Project アイテムを、ここで一括管理するためのスキル。
`<このスキルのディレクトリ>` は、この `SKILL.md` が置かれているディレクトリを指す。

## 前提

- `gh` CLI がインストールされ、`project` スコープ付きでログインしていること（`gh auth refresh -s project`）。
- 設定ファイル `~/.config/my-tasks/config.json`（環境変数 `MY_TASKS_CONFIG` で変更可）があること。無い場合は、`config.example.json` をコピーして作るようユーザーに案内する。

### 設定ファイルの項目

| 項目 | 内容 |
|---|---|
| `key` | 表に出す短い名前 |
| `owner` | Project を持つ Organization またはユーザー |
| `number` | Project の番号（URL の `/projects/<番号>`） |
| `done` | 完了扱いのステータス。`list` では表示しない |
| `include` | （省略可）指定すると、`list` ではこのステータスのアイテムだけを表示する |

## 手順

1. 一覧を取得して、出力された Markdown 表をそのままユーザーに表示する。

   ```bash
   python3 <このスキルのディレクトリ>/scripts/tasks.py list
   ```

   `done` や `include` で隠れているものも見たいと言われたら `list --all` を使う。

2. ユーザーが「3 を In Progress に」のように指示したら、表の番号を特定して変更する。
   ステータス名の候補は `tasks.py statuses` で確認できる。プロジェクトごとに選択肢が違う点に注意する。

   ```bash
   python3 <このスキルのディレクトリ>/scripts/tasks.py set <番号> "<ステータス名>"
   ```

   - 番号は直前の `list` の結果（`~/.cache/my-tasks/last.json`）に対応する。別セッションで番号が古い可能性がある場合は先に `list` をやり直す。
   - 複数件の変更をまとめて指示された場合は、変更内容を1行ずつ列挙してから順に実行する。
   - 指示がタイトルの一部などで曖昧な場合や、完了扱いのステータスへの変更は、対象を示して確認してから実行する。
   - `include` に無いステータスへ変えると、次回からそのアイテムは `list` に出なくなる。その旨を一言添える。

3. 変更後は `list` を再実行して最新の表を表示する。

## 下書き（チケット化前のローカルメモ）

`list` の出力には、GitHub の表の下に「下書き」表（番号は D1, D2…）が続く。両方の表をユーザーに表示する。
下書きは `~/.local/share/my-tasks/drafts.json` に保存され、GitHub には何も送らない。

- 「〇〇を下書きで」「下書きに追加」と言われたら追加する。タイトルはユーザーの言葉をそのまま使う。

  ```bash
  python3 <このスキルのディレクトリ>/scripts/tasks.py draft add "<タイトル>"
  ```

- 「D2 消して」と言われたら削除する。

  ```bash
  python3 <このスキルのディレクトリ>/scripts/tasks.py draft rm D<番号>
  ```

- 下書きをチケット化したいと言われたら、どのリポジトリに Issue を作るか・どのプロジェクトとステータスに入れるかを確認してから作成し、作成できたら下書きを削除する。
