# herdr-session-push: 別セッションへ非同期に指示を送る

> Herdr 専用のスキルです。`<このスキルのディレクトリ>` は、この `SKILL.md` が置かれているディレクトリを指します。

## 1. Herdr の中で動いているか確認する

```bash
test "${HERDR_ENV:-}" = 1
```

失敗したら「Herdr の外で動いているため使えません」と伝えて止まります。

## 2. 対象のペインを特定する

`<workspace:pane>` は、`<ワークスペースのラベル>:<ペインIDの後半>`（例: `myapp:p0`）です。`/herdr-tree` に出る形をそのまま使えます。前にプロンプト記号や `in` が付いたまま貼られても構いません。

```bash
<このスキルのディレクトリ>/scripts/resolve-target.sh "<貼り付けられた文字列>"
```

成功すると `{"pane_id":"w1:p0","agent":"claude","agent_status":"idle","cwd":"..."}` が返ります。失敗した場合（ワークスペース名の重複、ペインが見つからない等）は、標準エラーの内容をそのまま伝えて止まります。推測で別のペインを選ばないでください。

`<workspace:pane>` が指定されていない場合は、`/herdr-tree` スキルがあればそれでツリーを表示し、無ければ `herdr workspace list` と `herdr pane list` で候補を示して、どのペインかを聞きます。

## 3. 送ってよい相手か判定する

| 状態 | 対応 |
|---|---|
| 送り先が自分自身（`$HERDR_PANE_ID` と同じ） | 送らずに止まる |
| `agent` が `null`（エージェントがいない普通のシェル） | 送らない。`agent prompt` はエージェント専用で、シェルに文章を打ち込むと意図しないコマンドとして実行されうるため。普通のコマンドを実行したい場合は、ユーザーに確認してから `herdr pane run` を使う |
| `agent_status` が `blocked`（承認や質問の待ち） | 送らない。画面を `herdr agent read` で確認し、相手が何を待っているかをユーザーに伝える |
| `working`（作業中） | 送れるが、相手の作業の途中に割り込む形になる。ユーザーに一言確認する |
| `idle` / `done` | そのまま送る |
| `unknown` | 相手の状態が判別できていない。ユーザーに確認する |

## 4. プロンプトを整理する

指示が引数に無い場合は、直前までの会話の流れから「何を相手に頼みたいか」を読み取ります。読み取れなければ、1つだけ質問します。

送り先のセッションは、この会話の内容を一切知りません。そのため、次の項目を含めた「これ1通だけで作業を始められる」文章にします。

- **やってほしいこと**（最初の1〜2文で結論から書く）
- **背景**: なぜ必要か、これまでに分かっていること。会話の中で確定した事実だけを書き、推測は「推測」と明記する
- **対象**: ファイルパス、PR番号、ブランチ名、コマンドなど具体的なもの。相手のペインの `cwd` と異なる場所を指す場合は、絶対パスで書く
- **制約**: やってはいけないこと、確認が必要な操作（コミット、push、本番への変更など）
- **終わったときの報告のしかた**: 何をどの形で返してほしいか

注意点:

- 会話の生ログやエラー全文をそのまま貼らない。必要な部分だけを抜き出す。
- APIキー、トークン、パスワードなどの機密情報は含めない。
- 依頼内容を勝手に広げない。ユーザーが言っていない作業を足さない。
- 「完了したらこちらに返信してほしい」とユーザーが望んだ場合に限り、`herdr agent prompt $HERDR_PANE_ID "<報告文>"` で返してもらうよう末尾に書く（自分のペインIDは `$HERDR_PANE_ID` の値を展開して埋め込む）。

## 5. 非同期で送る

`--wait` を付けません。送ったらすぐ戻り、相手の完了は待ちません。

```bash
herdr agent prompt "<pane_id>" "$(cat <<'PROMPT'
<整理したプロンプト>
PROMPT
)"
```

## 6. 結果を報告する

次の3点だけを短く伝えます。

1. 送り先（`myapp:p0` と、解決したペインID）
2. 送ったプロンプトの全文（ユーザーが後から確認できるようにする）
3. 相手の結果は `/herdr-session-pull <workspace:pane>` で受け取れること

## この手順を守らなかった場合に起きること

- 手順 2 を飛ばして推測でペインを選ぶと、別の作業をしているセッションに指示が入り、そのセッションの作業が壊れます。
- 手順 3 の「`agent` が `null`」の確認を飛ばすと、指示文がシェルのコマンドとして実行されます。
- 手順 4 で背景や絶対パスを省くと、相手は会話の文脈が無いため、聞き返しで止まるか、誤ったファイルを対象に作業を進めます。
